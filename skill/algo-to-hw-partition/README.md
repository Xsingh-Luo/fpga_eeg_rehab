# 从算法描述推导软硬件划分

> 类型：**提示词工作流**（可复用的提问模板 + 判断规则）
> 验证状态：✅ 完整走过一轮，产出的划分已实现并上板

---

## 1. 适用场景

- 有一段算法要搬到 SoC（Zynq / PYNQ / 任何带处理器的 FPGA）上，**不知道该切在哪**
- 已经切了，但被质疑「为什么放这边」「这样以后升级够不够」
- 有人要求「PL 和 PS 都尽可能用上」「资源不能超」

**不适用**：算法本身还在迭代、结构没定；或纯 FPGA（无处理器）场景。

---

## 2. 核心思路：先算，再切

> **划分决策必须能被核算。** 凡是"因为 PL 快"这种理由，都站不住——要算到数字。

### 四步法

```
① 列每级的计算特征
     每级回答四个问题：算多少次？有无数据依赖？节拍要求？能否线性化？

② 标注实时约束来源
     哪些环节由外部时钟驱动（不能等）、哪些可以攒批

③ 判断可折叠性  ★ 最关键
     这个算子能不能离线算好、折进下一级的参数里？

④ 算资源与延迟
     时间复用 vs 全并行，各自的 DSP/BRAM/周期数
```

### 判断规则（按优先级）

| 规则 | 判据 | 归属 |
|---|---|---|
| **R1 可折叠** | 离线可算、且能折进下游参数矩阵 | **不占硬件**（最优先争取） |
| **R2 外部时钟驱动** | 数据按固定节拍到、不能等 | **PL** |
| **R3 无控制流** | 纯流式、规则计算 | **PL** |
| **R4 需矩阵分解/迭代** | EVD、SVD、收敛判断、分支 | **PS** |
| **R5 需 OS** | 文件系统、图形、网络 | **PS** |
| **R6 离线一次性** | 训练、标定、参数生成 | **PC** |

> **R1 是最值钱的一条。** 本项目最大的精度提升（+2.94 pp）恰恰来自一个可折叠算子
> （白化矩阵折进投影矩阵），PL 一行代码没改。

---

## 3. 提示词模板

### 模板 A：初次划分

```
我有一段算法要搬到 <芯片型号> 上，希望 <明确的性能/实时性目标>。
算法流程是：<逐级列出>

请按下面的顺序分析，每一级都要给出量化依据：
1. 每级的计算次数、数据依赖、节拍要求
2. 哪些算子可以离线折叠进下游参数（这是第一优先）
3. 剩下的按「外部时钟驱动 / 控制流复杂度 / 是否需要 OS」分配 PL、PS、PC
4. 给出资源估算（DSP/BRAM/LUT）与延迟估算，注明是估算还是实测
5. 明确写出：哪些结论是算过的，哪些只是推断
```

### 模板 B：被质疑时

```
有人质疑我的划分（<对方的具体理由>）。
请用数字重新核算这个质疑是否成立，不要用形容词。
如果我的原论证是错的，直接指出错在哪、漏算了什么。
```

### 模板 C：要求"两边都用上"

```
我的诉求是 PS 和 PL 都尽可能用上，但不要为了用而用。
请回答：PS 能不能干一件 PL 干不了的事？
如果能，具体是什么？如果不能，说明为什么不该拆。
```

> **模板 C 是本项目最重要的一次提问。** 它把问题从"怎么分配"换成了"什么只有 PS 能做"，
> 直接导向了「PS 做矩阵特征分解、PL 只做矩阵乘」的分工。

## 4. 已验证的效果

本项目（EEG 二分类，Zynq-7020）的划分结果：

| 环节 | 归属 | 依据 |
|---|---|---|
| UART 接收 + 包解析 | PL | R2（115200 无流控，占用 71.6%）+ R3 |
| 滤波 / 投影 / 滑动窗 / 判决 | PL | R2 + R3 |
| **欧氏对齐白化** | **无（折叠）** | **R1**：离线算好后折进投影矩阵 |
| 矩阵特征分解（在线自适应用） | PS | R4 |
| 参数管理 / 可视化 / 记录 / 范式呈现 | PS | R5 |
| 训练与参数生成 | PC | R6 |

**效果**：精度提升里最大的一项（+2.94 pp）**零硬件成本**；PL 侧延迟约 4 µs，确定无抖动。

### 反例：一次被推翻的论证

最早的理由是「PS 会丢字节，所以要放 PL」。被追问后重新核算：

- 只算了 UART 硬件 FIFO **64 B = 5.5 ms**
- **漏算了 Linux tty 缓冲 4 KB ≈ 355 ms**
- 结论：**"PS 会丢字节"这个论据基本不成立**

换成四条可核算的理由（验证边界 / 少一个转发接口 / 样本节拍 / 引脚可及性）后，论证才站得住。

> **教训**：一条论证只要有一处没算，整个结论就不可信。

---

## 5. 失效条件

| 条件 | 说明 |
|---|---|
| 算法含**在线迭代/自适应** | 折叠性失效——参数随数据变，必须每轮重算 |
| 节拍极快（单通道 > MSPS 级） | 时间复用不够，必须全并行，资源估算要重来 |
| 无处理器的纯 FPGA | PS 一侧的规则不适用 |
| 数据依赖分支多 | R3 不成立，需要状态机而非流水线 |

---

## 6. 来源

- **失败**：原论证漏算 tty 缓冲，被用户当场质疑
- **失败**：曾按"算法运算量"估 DSP 只要 ~20，实测 194（**低估 10 倍**）——
  因为实现选了"8 通道全并行"架构，而估算时按时间复用算的。
  **教训：架构选择对资源的影响远大于算法运算量本身。**
- **观察**：把白化折叠进投影后，下游完全感知不到它的存在——证明 R1 的价值
