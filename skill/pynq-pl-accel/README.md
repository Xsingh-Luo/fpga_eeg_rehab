# PL 加速器在 PYNQ 上的移植与上板清单

> 类型：**通用 PYNQ 技能包（加分项）** — 与本队题目、板卡**均不绑定**
> 验证状态：
> ✅ **"换板只改 3 处"的架构模式已在 Zynq-7020 板（ZYNQ7020-484）上实现并上板**
> ⚠️ **PYNQ-Z2 为规划中的演示板，实体尚未上板**（只完成了 XDC 与编译开关，未跑实物）
> ⚠️ 与 PYNQ 版本/驱动相关的条目来自公开资料与调研，**未在 PYNQ 上实测**

适用于任何「把 PL 加速器接到 Zynq PS 上」的题目：图像加速、信号处理、神经网络推理都适用。

---

## 1. 适用场景

- 已有一个能跑通的 PL 加速器，要接到 PYNQ / PetaLinux 上
- 想换板卡（不同 Zynq 开发板）但不想重写 PS 代码
- 上板后「能加载 bitstream 但读不到数据」/「跑一次就挂」

**不适用**：纯 RTL 仿真阶段；或板上没有 PS（纯 FPGA）。

---

## 2. 核心方法：把板级差异隔离到 3 个地方

**这是本包最有价值的一条经验。** 前期多花半天，后期换板省一周。

```
┌─────────────────────────────────────────────────┐
│  与板卡无关（不要写死任何板级信息）              │
│  · PL 逻辑（RTL / HLS）                          │
│  · PS 应用代码（C / Python）                     │
│  · 参数文件与协议                                 │
└─────────────────────────────────────────────────┘
              │  只在这 3 处允许出现板级差异
              ▼
   ① XDC 引脚与 IOSTANDARD      <board>.xdc
   ② AXI 基地址                 编译期宏 / 运行时从 overlay 读
   ③ 编译目标（器件、时钟）      make BOARD=<name>
```

### 落地检查表

| 检查项 | 做法 |
|---|---|
| PS 代码里**没有**硬编码 AXI 地址 | 用宏或从 overlay / `/sys` 读 |
| PS 代码里**没有**硬编码引脚/端口名 | 引脚只在 XDC |
| **PL 时钟来自 PS 的 FCLK** | 不要用板载晶振——换板频率就变了 |
| 器件型号只出现在编译脚本 | 不要散落在源码里 |
| XDC 按板卡命名并存两份以上 | 便于随时切换 |

> **反例**：如果 PL 时钟取板载 125 MHz，换到没有 125 MHz 晶振的板子上，
> 所有分频系数都要重算，时序也要重跑。取 PS 的 FCLK 就完全没这个问题。

## 3. 上板前的四步验收

```
① 环境自检         bash env_check.sh
② 回放跑通         用固定测试向量（不是实时源）跑一次完整数据流
③ 逐级对拍         PL 输出 vs 整数参考，逐位一致
④ 再上实时源       接通真实数据源，先短时（15 s），再长时（30 min）
```

### ① 环境自检

```bash
bash skill/pynq-pl-accel/env_check.sh
# 可选：把 FTDI 缓冲延迟从默认 16 ms 改成 1 ms
sudo bash skill/pynq-pl-accel/env_check.sh --fix-ftdi
```

检查：平台版本、bitstream 加载通道、串口与 `latency_timer`、ModemManager 抢占、内存与挂载。

### ② 回放优先

**永远先跑回放，再上实时源。** 回放的好处：
- 输入完全确定 → 出了问题能二分定位到"数据源"还是"处理链"
- 可重复 → 每次改动后都能跑同一个回归
- 演示时可作降级路径

### ③ 逐级对拍，不是只看最终结果

至少冻结四样：**输入 + 参数 + 复位状态 + 评分窗口**。
在每一级 dump 中间结果与整数参考比较。

> 只比最终结果的话，「准确率差不多」会掩盖中间某级的偏差。

### ④ 先短时后长时

15 秒能过不代表 30 分钟能过。长时间跑最容易暴露：FIFO 溢出、计数器回绕、内存泄漏。

## 4. 踩坑清单（PYNQ / Zynq Linux）

| # | 坑 | 触发条件 | 处理 |
|---|---|---|---|
| **1** | **PYNQ v4.0.0 起不再支持 Zynq-7020（Z1/Z2）** | 用 PYNQ 4.x 镜像配 7020 板 | 停在 v2.7 / v3.x；或改用 PetaLinux |
| **2** | **PYNQ 镜像与板卡不通用** | 把别的 Zynq 板镜像刷到 7020 板 | DDR/时钟/设备树都不同，必须用对应镜像 |
| **3** | **USB Host 模式默认没开** | 要接 USB 设备（采集卡、串口） | PYNQ 的 device tree 未设 `dr_mode = "host"`，需打补丁；部分板要短接跳线 |
| **4** | **USB 转串口驱动缺失** | 内核没编 `ftdi_sio` 等模块 | `modinfo ftdi_sio` 先确认；缺了只能换板或重编内核 |
| **5** | **FTDI `latency_timer` 默认 16 ms** | 用 FTDI 类 USB 串口 | `echo 1 > /sys/bus/usb-serial/devices/ttyUSBx/latency_timer`；**每次重新插拔都会恢复默认** |
| **6** | **ModemManager 抢串口** | 发行版默认装了 ModemManager | 加 udev 标签 `ID_MM_DEVICE_IGNORE` |
| **7** | **PL 时钟取板载晶振** | 图省事 | 改取 PS 的 `FCLK_CLK0`（见 §2） |
| **8** | **AXI 基地址随 overlay 变** | 换 bitstream 后地址变了 | 运行时从 overlay 动态读，不要硬编码 |
| **9** | **参数下发不校验** | 只写不看返回值 | 写入后**回读比对** + CRC；失败要报错而不是静默继续 |
| **10** | **断电不都是安全的** | 演示现场直接拔电 | 走 init 正常关机；确认持久存储已同步 |

### 坑 5 的补充说明

`latency_timer` 是「芯片里攒够多久再上报」。默认 16 ms 意味着**端到端延迟凭空多 16 ms**。
改成 1 ms 后：延迟降低，但会带来每毫秒一次的状态中断（这是 FTDI 自身的取舍）。

**关键细节**：Dongle 重新枚举后（拔插、重启），该值**会恢复默认 16**。
所以每次采集前都要重设并**读回确认**。

## 5. 参数下发的最小可靠实现

```c
/* 1) 复位到已知状态 */
axil_write(CTRL, 0x2);          /* soft_reset */
usleep(10000);
axil_write(CTRL, 0x0);

/* 2) 按块写入 */
for (blk in blocks) {
    axil_write(PARAM_ADDR, blk.id | (blk.len << 24));
    for (i = 0; i < blk.len; i++) axil_write(PARAM_RAM, blk.data[i]);
    axil_write(PARAM_COMMIT, 1);

    /* 3) ★ 必须等校验结果，不要只等"写完成" */
    if (!wait_bit(STATUS, PARAMS_CRC_OK, TIMEOUT))
        return ERR_CRC;          /* 拒绝使用半截参数 */
}

/* 4) ★ 回读抽查，确认真的写进去了 */
for (k in sampled_params)
    if (axil_read(PARAM_RB[k]) != expected[k]) return ERR_READBACK;

/* 5) 启动 */
axil_write(CTRL, 0x1);
```

**为什么必须回读**：参数加载失败如果静默继续，表现是「精度莫名掉了几个点」——
这是最难查的一类问题。

| 项 | 结果 | 验证平台 |

## 7. 失效条件

| 条件 | 说明 |
|---|---|
| PYNQ 版本改动 | 4.x 起不支持 7020；overlay API 也可能变，逐版本核对 |
| 换到非 Zynq 的 MPSoC | `xdevcfg` / `fpga_manager` 加载方式不同 |
| 板卡 DDR/时钟差异大 | 即使只换 XDC 也可能要重做时序约束 |
| PS 侧开启缓存/一致性 | AXI DMA 场景要处理 cache 一致性，本包未覆盖 |
| 需要 USB Host 但板卡未引出 | 硬件限制，软件无解 |

---

## 8. 来源

- **观察**：为了让"换板只改 3 处"成立，前期把板级信息全部隔离到 XDC / 基地址 / 编译目标；
  后期换板确实只改了这三个地方
- **失败**：早期把 PL 时钟接板载晶振，导致换板时所有分频系数都要重算
- **失败**：参数下发只检查写成功、不检查 CRC，出现过"参数半截生效"导致精度下降
- **调研**：PYNQ v4 移除 7020 支持、USB Host 模式需补丁、FTDI latency_timer 默认 16 ms
  —— 这些来自公开资料，**本队尚未在 PYNQ 上实测**，使用时请自行验证

> **诚实提示**：本包中标注 ⚠️ 的条目是调研结论，不是实测结论。
> 如果你在 PYNQ 上验证了其中任一条，建议回来更新这一节。
