# 静默错误猎杀

> 类型：**踩坑清单 + 校验脚本**
> 验证状态：✅ 本项目据此抓到 **6 个静默错误**（不报错、结果"看着合理"）

---

## 1. 适用场景

- 结果"看着合理"，但你不确定它对不对
- 改了核心数值代码，不知道该验证什么
- 准确率比预期低几个点，找不到原因

**不适用**：崩溃类错误（有异常信息）、纯逻辑/时序 bug（用波形和断言查）。

---

## 2. 什么是"静默错误"，为什么最危险

| 类型 | 是否报错 | 是否容易被发现 | 危险度 |
|---|---|---|---|
| 崩溃 | ✅ 报错 | 立刻 | 低 |
| 结果明显异常（如 50%） | ✗ | 一眼看出 | 中 |
| **结果"看着合理"**（如 74%，"差不多"） | ✗ | **几乎不可能** | **高** |

本项目的实际数据：**6 个错误中有 3 个跑起来完全正常、数字也在合理区间。**

**唯一可靠的办法：主动构造可手算的小例子去撞。**

---

## 3. 三类高频静默错误

### 类型 A：矩阵方向 / 下标约定

**陷阱**：当矩阵恰好是**方阵**时，转置错误完全不报错。

本项目实例（空间滤波）：

```python
# 错误：算的是 W·x（pattern 矩阵）
Z = np.einsum("cd,ndt->nct", W, X)
# 正确：z = Wᵀx（W 的列才是滤波器）
Z = np.einsum("cj,nct->njt", W, X)
```

潜伏原因：数据是 **3 通道**，`W` 是 3×3 方阵 → 不报错、结果 74%（合理区间）。
直到测另一组参数、矩阵变成 3×2 非方阵才崩溃暴露。

**自检**：

```python
W = np.array([[1., 2.], [3., 4.]]); x = np.array([10., 100.])
assert np.allclose(np.einsum("cj,nct->njt", W, x[None,:,None]).ravel(), [310., 420.])
```

### 类型 B：量纲 / 单位换算

**陷阱**：从频率响应算群延迟时，`-dφ/df` 的单位是 **rad/Hz**，
换算成**秒**要除以 **2π**。漏了之后所有延迟数字偏大 **6.28 倍**。

**自检方法：找一个解析值已知的对象做交叉验证。**

```
FIR 对称抽头的群延迟必然是 (N-1)/2 个采样点
→ 128 抽头 @250 Hz 必然是 254 ms
→ 若代码算出 1596 ms，1596/254 = 6.28 ≈ 2π  ← 立刻定位
```

> **通用招式**：任何量纲换算，都要找一个能用公式直接算出来的特例做对拍。

### 类型 C：折叠 / 合并的层次

**陷阱**：把算子 A 折进下游参数后，输入却仍然是"已经过 A 处理"的数据。

本项目实例（白化折进投影）：

$$W_{\text{eff}} = M^TW,\qquad W_{\text{eff}}^T x = (M^TW)^Tx = W^TMx = W^T x_{\text{aligned}}$$

所以折叠后**必须喂未对齐的原始数据**。喂已对齐的等于把 $M$ 施加两次。

**后果**：准确率从 80.3% 掉到 74.5%，**代码不报任何错**。

**自检**：

```python
ref    = W.T @ (M @ x)          # 正确
folded = (M.T @ W).T @ x        # 折叠，喂原始数据  → 应与 ref 相等
double = (M.T @ W).T @ (M @ x)  # 折叠，又喂已对齐  → 会出现明显偏差
assert np.allclose(folded, ref)
assert not np.allclose(double, ref)
```

## 4. 使用方法

```bash
python numeric_selfcheck.py          # 跑三类自检
python numeric_selfcheck.py --only T # 只跑矩阵转置
```

**建议加进你的回归测试**：每次改动核心数值代码，这三项都跑一遍（不到 1 秒）。

### 扩展：为你的项目补充自检

| 你的项目有什么 | 该写什么自检 |
|---|---|
| 矩阵乘法 / 张量下标 | 用 2×2 或 3×2 的**非方阵**测试，别用方阵 |
| 单位换算（角度/频率/时间） | 找解析解已知的特例（如 FIR 对称抽头的群延迟） |
| 参数折叠 / 预计算 | 断言"折叠路径"与"安全路径"输出逐位一致 |
| 定点量化 | 用满量程附近的数测试（本项目的 `b1≈−1.99`） |
| 索引 / 查表 | 测试边界值（0、最大值、最大值+1） |

## 6. 失效条件

| 条件 | 说明 |
|---|---|
| 错误只在**特定数据**上触发 | 小例子撞不出来，需要真实数据的边界样本 |
| 错误在时序/握手层 | 需要波形断言，不是数值自检 |
| 依赖库版本差异 | 自检要跑在与生产相同的环境里 |

---

## 7. 来源

- **失败**：`einsum` 下标写错，方阵让它静默通过；直到换参数变成非方阵才崩溃
- **失败**：群延迟漏 2π，靠 FIR 解析值交叉验证抓到（1596 / 254 = 6.28 ≈ 2π）
- **失败**：折叠后仍喂已对齐数据，准确率掉 5.8 pp 且无任何报错
- **观察**：所有静默错误的共同点——**它们都产生"看起来合理"的结果**，
  所以人工 review 和"跑通了"都不能作为验证
